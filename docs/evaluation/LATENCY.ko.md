# Laya와 일반 LLM 소요 시간 비교

![동일 판단 작업 시간 비교](latency-comparison.png)


## 실측 결과

| 모델·장치 | 유효 요청 | 동일 표본 요청 합계 | 전체 요청 시간 추정 |
|---|---:|---:|---:|
| Laya multilingual · GPU | 60/60 | 44.92초 (0.75분) | 127.6분 |
| Qwen3.6 35B · CPU | 60/60 | 1841.21초 (30.69분) | 6821.5분 |

각 모델에서 960개 선택형 응답이 검증됐습니다. 제시한 배율은 장치가 다른 이 설치의 시간비입니다.

동일 표본에서 일반 LLM / Laya 시간비는 **40.99배**, 차이는 **1796.29초**입니다.

| 근거 종류 | Laya 첫 평가 평균/요청 | Qwen 첫 평가 평균/요청 | 첫 평가 요청 수/모델 |
|---|---:|---:|---:|
| 행 | 0.711초 | 52.686초 | 10 |
| 셀 | 0.187초 | 36.253초 | 10 |
| 행 쌍 | 1.342초 | 63.148초 | 10 |

| 평가 회차 | Laya 시간 합 | Qwen 시간 합 | 요청 수/모델 |
|---|---:|---:|---:|
| 첫 평가 | 22.41초 | 1520.87초 | 30 |
| 같은 표본 반복 | 22.51초 | 320.34초 | 30 |

## 비교 작업

- 실제 메타분석 입력에서 행·셀·선언된 행 쌍을 각각 10개씩 무작위 추출했습니다. 난수 시드는 `20261002`이고 결과에 따라 표본을 바꾸지 않았습니다.
- 30개 서로 다른 근거 단위를 각각 2회 평가합니다. 모델별 60개 HTTP 요청, 요청당 8관점 × 탐색·초점 = 16개 선택형 질문입니다.
- 두 모델에 같은 전체 근거와 질문·선택지 정의를 전달했습니다. Qwen은 모든 질문 ID의 선택 결과를 JSON으로 생성합니다. 근거·질문을 잘라내거나 실패를 완료로 계산하지 않습니다.
- 이 시험은 **처리 시간의 표본 비교**입니다. 기존 Laya 전체 전수 검사와 별개이며 일반 LLM의 전체 7,005개 단위 검사 완료를 뜻하지 않습니다.

## 설치와 측정 조건

- Laya multilingual: GPU, 리비전은 `latency-results.json`에 고정했습니다. 토크나이저의 전체 근거 길이 검사도 요청 시간에 포함합니다.
- 일반 LLM: Ollama의 `qwen3.6:35b`, Q4_K_M, 실제 모델 메타데이터는 36.0B입니다. 모델 파일 해시를 결과에 기록합니다. `think=false`, temperature 0, context 32,768, 최대 출력 2,048토큰입니다.
- 호스트: NVIDIA GB10, aarch64. **현재 Ollama 실행 로그는 Qwen 텐서를 CPU_REPACK 버퍼에 로드한 것으로 나타납니다. GPU를 요청했으나 GPU 실행으로 확인되지 않았습니다.** 따라서 Laya GPU와 이 설치의 Qwen CPU 비교이며, 동등한 GPU 환경에서의 모델 자체 속도 배율로 해석할 수 없습니다.
- 각 모델의 첫 워밍업은 별도로 기록하고 본 측정에서 제외합니다. Qwen은 측정 전 이미 로드돼 있을 수 있어 워밍업을 순수 콜드 스타트로 해석하지 않습니다.
- 동시에 하나씩 요청하고, Laya 단계 다음에 Qwen 단계를 실행했습니다. 모델 실행 순서는 무작위 교차가 아닙니다. 표본 내 순서는 섞었습니다.
- 스킬의 답변 캐시는 사용하지 않았습니다. 서버의 네이티브 KV·프롬프트 캐시는 허용됩니다. 반복 측정은 서로 독립인 새 데이터 60개가 아닙니다.
- 시간은 HTTP 요청 시작부터 응답 형식·질문 누락 검증까지입니다. Laya는 선택과 확률을 함께 반환하고, Qwen에는 선택 ID만 요청했습니다. Qwen 확률 생성이나 자유문장 연구 질문 작성 시간은 포함하지 않습니다.
- Ollama가 보고하는 세부 시간의 단위는 나노초이며 원래 값도 보존했습니다. [Ollama 공식 Chat API](https://docs.ollama.com/api/chat)

## 그래프 읽기

- 왼쪽: 동일 표본의 실제 요청 시간 합계입니다. 로드·워밍업과 기존 전수 검사의 중단 시간은 포함하지 않습니다.
- 오른쪽: **첫 평가의 평균만** 사용해 `행 평균 × 1,790 + 셀 평균 × 533 + 쌍 평균 × 4,682`로 계산한 **전체 요청 시간의 단순 추정치**입니다. 같은 입력을 반복하며 생기는 캐시 효과를 전체 새 데이터 시간에 섞지 않습니다. 표본 구성이 전체와 다르므로 모든 표본의 평균에 7,005를 곱하지 않습니다. 새 실행의 준비·검증·재시도·장치 경쟁·문헌 검색 시간은 추정하지 않습니다.
- 기존 Laya의 143.6분은 중단·재개·검증을 포함한 경과 시간이므로 현재 실측과 직접 비교하지 않습니다.
- Jev API는 시간 미측정입니다. 이 결과는 선택형 처리 속도이며 후보의 타당성·신규성·발굴 품질 비교가 아닙니다.
- 첫 시도의 JSON 배열 응답은 기대한 16개 선택형 응답 계약과 일치하지 않아 해당 시도는 유효 비교에서 제외했습니다. 모든 질문을 필수 키로 지정하는 JSON 객체 방식으로 다시 측정했습니다. 실패 시도를 성공처럼 포함하지 않습니다.

## 재현

원본 실행 데이터와 로컬 모델 설치를 가진 환경에서:

```bash
python scripts/benchmark_latency.py --run runs/YOUR_FROZEN_RUN \
  --out runs/YOUR_NEW_TIMING_RUN --model qwen3.6:35b --per-kind 10 --repeats 2
```

배포된 비식별 시간값으로 PNG만 다시 생성하려면:

```bash
python -m pip install -e '.[plots]'
python scripts/plot_latency.py --font /path/to/Korean-font.otf
```

`latency-results.json`에는 모델 정보·검사 계약 해시·종류·표본 순번·시간만 배포합니다. 근거 원문, 행 ID, 모델 답변, 로컬 개인 경로는 배포하지 않습니다. 원본과 답변은 로컬 `runs/`에 보존됩니다.
