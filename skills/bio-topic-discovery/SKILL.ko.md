# 바이오 연구 후보 전수 검사

[English](SKILL.md) | **한국어**

엔진은 이 저장소의 `bio_topics` 패키지입니다. 저장소에서 `pip install -e .`로 설치하세요. `scripts/run.py`는 저장소의 엔진 또는 설치된 패키지를 찾습니다. `--project PATH`나 `BIO_TOPIC_DISCOVERY_ROOT`로 별도 설치를 선택할 수 있습니다. 새 데이터와 실행은 [references/workflow.ko.md](references/workflow.ko.md)를 읽으세요.

## 새 작업의 기본 설계

새 계획·재설계·재실행 전에 [근거 공유 전수 설계](references/efficient-inspection.ko.md)를 읽습니다. 원본 전 행과 선언 관계를 보존하면서 연구×유전자 카드(메타분석은 임상 질문×분석 세트)를 공유하고, 사실 계산과 과학적 질문을 분리합니다. 해당되지 않는 질문과 같은 근거의 반복 처리를 줄입니다. 기존 행·셀·쌍 × 8종 방식은 기본값이 아닙니다. `--legacy-deg`는 사용자가 의도한 역사적 계약일 때만 쓰며 자동 우회하지 않습니다.

설계상 연결·실제 모델 응답·과학적 검증을 따로 보고합니다. 새 카드 실행기·다중 카드 배치·의존 캐시가 미구현이면 그 상태를 밝히고 구현·검증부터 수행합니다. 기존 방식을 조용히 재개하거나 완료·속도 개선을 먼저 주장하지 않습니다.

## 핵심 계약

- 어댑터와 사실 엔진은 입력·계산을 준비합니다. **선언된 모든 검사 단위에 Laya/Jev의 실제 응답이 있어야 후보 발견이 완료**됩니다. FDR, 중요도, 상위 K개, 시간·개수 제한으로 검사 범위를 줄이지 않습니다.
- 실행 전에 원본–카드 연결, 해당 질문, 선언 관계·지원 합성 시나리오의 목록을 고정합니다. 과학적 쌍 범위를 사용자 의도에 맞게 선언하고 범위와 검사 수를 알립니다. 행 쌍 제외 또는 다른 범위를 임의로 사용자의 전수 요청으로 바꾸지 않습니다.
- 약한 근거·보류·차단 행도 검사합니다. 합성이나 결론 사용의 승인 여부는 별도입니다. 프로파일의 unknown을 모델 추정으로 채우지 않습니다.
- 새 실행 폴더를 사용하고 원본을 보존합니다. 재개는 같은 입력·프로파일·코드·모델·토크나이저에서만 수행합니다. 오류 원인을 해결한 후 실패 검사만 재시도하며, 반복되는 영구 실패는 미완료로 보고합니다.
- 기본은 기존 로컬 Laya입니다. 서버를 재시작하거나 모델을 추가 로드하지 않습니다. 사용자가 Jev의 외부 근거 전송을 명시적으로 선택한 경우만 `--allow-external`을 사용합니다. API 키는 환경변수로 전달하고 노출하지 않습니다.
- 근거·질문·선택지를 자른 검사는 성공으로 인정하지 않습니다. 실패나 정보 부족을 후보 없음으로 바꾸지 않습니다.

## 수행

1. 원본 열과 실험·리뷰 맥락을 확인하고 연구별 JSON/YAML 프로파일을 만듭니다. 예제의 합성 연구 정의를 사용자 데이터에 복사하지 않습니다. 열 매핑 같은 기술 선택은 진행하고, 추정량·비교 방향·시점·전수 관계 범위처럼 결과를 바꾸는 미결 과학적 사항만 확인합니다.
2. 선택한 실행기가 선언 설계를 구현했는지 검증한 뒤 `plan`으로 `mapping.json`과 `manifest.json`을 확인합니다. 모든 원본 행이 포함되는지, 검사 범위와 합성 제외 사유를 설명합니다. 사용자 요청에 맞는 실행은 이어서 진행합니다.
3. `run`으로 전수 평가하고 진행을 알립니다. 같은 근거의 해당 질문을 묶고 개별 판단을 남깁니다. 한 카드의 질문 묶음과 다중 카드 배치를 구분합니다.
4. `verify`의 `verified`, manifest의 `completed`, 검사율 100%, 실패·미검사 0을 확인합니다. 합성 테스트·규칙 대체는 실제 모델 검사 증거가 아닙니다.
5. **`candidates.csv`를 기본 결과물로 전달**하고 클릭 가능한 절대 경로 링크를 제공합니다. CSV·JSONL·원본 근거를 함께 읽어 근거·확인 사항·검사 상태를 확인하고 간단히 요약합니다. 모든 후보는 CSV에 유지하며 Markdown/JSONL은 보조 자료입니다. 미완료 검사는 임시 결과로 표시합니다. 후보가 없으면 헤더만 있는 CSV와 검사 상태를 전달합니다. 명시적 허락 없이 비공개 근거가 담긴 후보 CSV를 공개 게시하지 않습니다.
6. 요청 범위에서 문헌과 System 2 검토를 이어갑니다. 후보별 관측/가설, 반대 근거, 반증 조건, 후속 분석·실험을 작성하고 출처를 남깁니다. 미확인 문헌·새 수치·인과·대사 흐름을 만들지 않습니다. 검토 완료와 사람의 채택을 자동 표시하지 않습니다.

메타회귀·깔때기 검정·진단정확도 공동 합성·복잡한 공분산 모형·긴 카드 자동 분할은 미지원입니다. 선언된 검사 계약의 완료를 모든 가능한 분석의 완료로 표현하지 않습니다. Jev 연결은 구현되어 있으나 실제 API 실행 검증은 별도입니다.

## 현재 품질 한계

후보 제목은 선택형 판단의 템플릿이며 합성 경고가 분류에 영향을 줄 수 있습니다. 검사 건수·선택 확률을 새로운 연구 주제의 수나 과학적 타당성으로 표시하지 마세요. 모델의 원래 표시와 후속 검토자가 작성한 질문을 구분하세요. 문헌·신규성·반증 가능성 검토는 별도입니다. 공개 컴퓨팅 시간과 결과 해석은 저장소 `docs/evaluation/`에 있습니다.

## 임상 질문·분석 세트별 메타분석 (v0.3)

`clinical.partition`으로 상위 질문·비교 층·민감도 항목을 선언합니다. 모형·lag·추적기간 차이를 기본적으로 상위 질문 ID에 넣지 않습니다. 실제 프로파일의 과학적 규칙은 연구자가 확인한 맥락을 사용하고, 합성 예제의 정의를 복사하지 마세요. 엔진 `docs/clinical-pipeline.ko.md`와 `profiles/meta.clinical.example.yaml`을 참고하세요.

독립 근거 수는 선택한 효과 행과 중복 처리 규칙이 있는 `analysis_sets.csv`에서 읽습니다. 기관·기간·모집 기준을 문서로 판단한 근거도 수준과 출처를 명시하면 지원하며, 미확정은 빈 값입니다. 모든 허용 대안을 검사하며 결과 방향·유의성·정밀도로 대표 추정치를 선택하지 않습니다. 논문 수는 별도 표시하고 가점은 기본 0, 켜더라도 확인된 참여자 집단당 최대 1회입니다. 순위는 검토 우선순위이며 통계 가중치나 근거 확실성으로 쓰지 않습니다.

`candidates.csv`는 상위 질문별 후보 묶음, `inspection_results.csv`는 전체 검사, `candidate_effects.csv`는 같은 질문의 반대·무효·배경·보류를 포함한 모든 효과 행과 역할의 연결표입니다. 프로토콜·사후 탐색·후속 검증 질문을 출처·시점과 함께 구분합니다. 등록되지 않은 질문과 데이터에서 새로 만든 가설은 사후 탐색으로 남깁니다. 검사 완료를 원문 대조·독립 이중검토·결과별 RoB 평가·합성 승인으로 표시하지 마세요. 각 단계의 실제 입력 근거가 있어야 해당 상태가 충족됩니다. 기존 실행은 저장된 소스로 재현하고 새 코드·규칙은 새 실행에 적용합니다.
