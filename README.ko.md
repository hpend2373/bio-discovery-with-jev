## 컴퓨팅 시간과 결과의 의미

![GPU 실측 요청 시간](docs/evaluation/latency-comparison.png)

같은 GPU에서 동일한 근거 입력 30개를 각각 2회 평가한 결과, Laya는 **45.07초**, Qwen3.6 35B는 **251.84초**가 걸렸습니다. 이 표본의 총 시간비는 **5.59배**, 차이는 **206.77초**입니다. 각 모델의 60개 요청과 960개 필수 선택이 응답 계약을 통과했습니다.

두 모델의 선택 결과 일치율은 **26.25% (252/960)**였습니다. 빠른 처리와 응답 완결성은 확인됐지만 동일한 판단 품질이나 과학적 타당성이 입증된 것은 아닙니다. 전문가 정답지와 통계적 유의성 검정은 사용하지 않았고, Jev는 시간 미측정입니다.

캡션과 자세한 측정 방법은 [컴퓨팅 시간과 결과 해석](docs/evaluation/LATENCY.ko.md)에 있습니다. 현재 엔진의 후보는 선택형 판단과 템플릿 제목을 사용하므로 구체화·문헌 확인·과학적 검토가 필요합니다.

DEG·오믹스 결과표와 메타분석 원장을 읽고 **로컬 Laya가 정의된 모든 검사 단위를 평가**합니다. 모델 이전의 FDR 필터, 상위 K개 선택, 후보 수 제한은 없습니다. 모델이 선택한 신호·초점에서 후보를 만들고, 모든 원본 행과 판단 기록을 연결합니다.

## 현재 제공하는 기능

- CSV/TSV/XLSX 열 매핑과 원본 값 보존. 수식 XLSX는 값으로 저장해야 합니다.
- 공통 출처·상태 정보와 DEG/메타분석 전용 필드.
- 모든 행, 비교 셀, 프로파일이 선언한 모든 행 쌍, 지원되는 합성 시나리오의 검사 목록 확정.
- 8개 연산자와 각 연산자의 초점 판단. 같은 근거의 질문을 묶어 모델 호출.
- 로컬 Laya HTTP 연결과 **실제 토크나이저로 근거·질문·선택지의 잘림 방지 확인**. 기존 모델 서버를 재사용하고 별도의 모델 가중치를 로드하지 않습니다.
- 명시적으로 선택한 Jev 연결. 고정 모델 버전과 API 키가 필요하며 자동 백엔드 전환은 없습니다.
- SQLite 검사 기록, 정확한 입력·모델·질문에 결합된 캐시, 중단 후 재개.
- 검사 목록 재생성, 원본 재파싱, 개별 응답 검증으로 전수 완료 확인.
- 발견된 **모든** 후보와 추가 확인 항목의 한국어 보고서·CSV·JSONL 출력.

## 바로 실행

Python 3.10 이상에서 `python -m pip install -e .`로 설치합니다. YAML은 PyYAML을 사용하고 JSON 프로파일은 추가 라이브러리가 필요 없습니다. XLSX는 내장 읽기 기능을 사용합니다.

프로젝트 폴더에서:

```bash
python3 -m bio_topics plan --input examples/deg.csv --profile profiles/deg.example.yaml --out runs/my-deg
python3 -m bio_topics run --out runs/my-deg
python3 -m bio_topics verify --out runs/my-deg
```

메타분석은 `examples/meta-clinical.csv`와 `profiles/meta.clinical.example.yaml`을 사용합니다. 예제는 합성 데이터이며 실제 생물학적 결과가 아닙니다.

사용자 데이터에는 예제 프로파일을 복사해 `synthetic_example: false`, 연구 질문, 열 매핑, 실험·연구 정의를 수정합니다. 프로파일에 선언하지 않은 과학적 정보를 추정해 채우지 않습니다.

## 전수 범위

`inspection.cell_fields`는 모든 행을 비교 셀로 나누는 기준입니다.

- `pairs: all`: 모든 행 쌍. n(n−1)/2개이므로 대규모 입력에서 비용이 커집니다.
- `pairs: within_groups`: `pair_group_by`로 선언한 그룹 내부의 모든 쌍.
- `pairs: none`: 행 쌍 검사를 계약에서 제외. 전체 행·셀 검사는 계속 수행합니다.

이 선택은 전수의 **과학적 범위**를 정의합니다. 낮은 모델 점수나 FDR 때문에 범위를 줄이지 않습니다. 실행 전에 `mapping.json`과 `manifest.json`의 `preflight`, 행·셀·쌍 수와 합성 제외 사유를 확인합니다. 쌍 범위가 연구 의도와 맞지 않으면 실행하기 전에 프로파일을 고쳐 새 계획을 만듭니다.

지원 범위 밖의 임의 조합·자유문장 가설 전체를 검사했다는 의미는 아닙니다. 각 검사 단위 × 선언된 모든 연산자에 실제 모델 결과가 있어야 합니다.

## 메타분석 계산

v0.1 합성은 같은 척도·단위·결과 정의·시점·비교군·단계·추정량·시간 기준점에서만 수행합니다. 척도를 자동 변환하지 않습니다.

- `synthesis.enabled: true`인 경우만 계산합니다.
- `synthesis_approved: true`, 미차단·미보류, 유효한 효과량·정밀도, 선언된 필수 메타데이터가 필요합니다.
- 보고된 SE는 분석 축을 선언해야 합니다. CI 역산은 명시된 정규 Wald 구간에만 적용합니다.
- 같은 연구 또는 선언된 공유 코호트는 의존성 묶음으로 연결합니다.
- `one_per_dependency_component`는 묶음마다 하나를 선택하는 **모든** 조합을 계산합니다. 중복 가능성 확인 자체를 대신하지 않습니다.
- `fixed_iv`, 선택적 `random_dl`과 묶음 하나씩 제외하는 민감도 계산을 지원합니다. 모두 탐색 계산이며 승인된 주 분석 결론이 아닙니다.
- 연구가 적을 때 DL/Wald 불확실성 해석은 제한됩니다. 메타회귀, 깔때기 비대칭 검정, 예측구간, 공분산을 쓰는 다변량 모형, 진단정확도 공동 합성은 현재 구현하지 않았습니다.
- 단일 비율·기술통계 등 미지원 척도의 행도 모델 검사에 포함하지만 합성은 수행하지 않습니다.

## 모델과 길이 한도

기본 Laya는 `http://127.0.0.1:8000`, `multilingual`입니다. 컨테이너 `laya-local-laya-serve-1` 안에서 같은 리비전의 토크나이저만 실행해 전송 내용을 확인합니다. 서버는 변경·재시작하지 않습니다.

`max_len`은 4096, `head_max_len`은 384로 시작합니다. 근거나 선택지가 잘릴 경우 해당 검사는 실패로 남습니다. 토큰 한도를 자동 우회하거나 일부 근거만 보내고 성공으로 표시하지 않습니다. 긴 카드의 계층적 분할·관계 재검사는 후속 확장 사항입니다.

Jev 사용은 새 프로파일에 다음을 선언합니다.

```yaml
backend:
  kind: jev
  model: jev-1.13.0 # 실제 사용 가능한 고정 버전으로 바꾸세요.
  max_body_bytes: 262144
```

`TYPESAFE_API_KEY` 환경변수를 준비하고 `run --allow-external`로 외부 근거 전송을 명시합니다. 키는 기록에 저장하지 않습니다. Jev는 연결 코드와 응답 검증을 구현했으나 실제 서비스 실행은 아직 검증하지 않았습니다. 서버 측 입력 처리는 로컬 토크나이저로 검증할 수 없으므로 Laya의 길이 검증과 같은 보장을 하지 않습니다.

## 재개·실패·완료

```bash
python3 -m bio_topics status --out runs/my-deg
python3 -m bio_topics run --out runs/my-deg
python3 -m bio_topics run --out runs/my-deg --retry-failed
```

성공한 판단은 재개 시 다시 요청하지 않습니다. 실패 원인을 해결한 후 `--retry-failed`를 사용합니다. 모델 오류를 규칙이나 다른 모델 결과로 대체하지 않습니다.

입력·프로파일·모델·토크나이저·코드가 달라지면 같은 실행으로 재개하지 않습니다. 실행 폴더에 소스 스냅샷을 보관하므로 기존 코드로 재개할 수 있습니다.

```bash
PYTHONPATH=/절대경로/실행폴더/source python3 -m bio_topics run --out /절대경로/실행폴더
```

프로젝트 바깥 폴더에서 위 명령을 사용해야 현재 작업 폴더의 새 코드가 우선 로드되지 않습니다.

완료 조건은 `manifest.json: completed`, `verification.json: verified`, 검사율 100%, 실패·미검사 0입니다. 정보 부족은 실제 판단 결과이고 연결 실패는 미완료입니다. 합성 응답을 사용하는 테스트는 검사율이 100%여도 과학적 완료로 인정하지 않습니다.

## 출력과 후속 검토

- **`candidates.csv`: 기본 결과물.** 후보별 질문, 범위, 원본 행 ID, 관측 근거, 한계, 반증 조건, 추가 확인 사항, 모델 판단과 검사·검증 상태를 담습니다. 모든 후보·추가 확인 항목을 유지합니다. 실행 완료 시 자동 생성하고 `candidate_csv`로 절대 경로를 반환합니다.
- `REPORT.ko.md` / `candidates.jsonl`: 보조 보고서와 구조화 기록.
- `decisions.jsonl` / `inspection.sqlite3`: 후보 없음까지 포함한 전체 판단 기록.
- `SYSTEM2-REVIEW.ko.md`: 문헌·기전·반증 조건·후속 실험 검토 절차.

검증된 실행의 CSV만 다시 내보내려면 `bio-topics report --out runs/실행폴더`를 사용합니다. 모델을 다시 호출하지 않습니다. CSV는 영문 열 이름과 UTF-8 BOM 인코딩을 사용하고, 복합 근거 셀은 JSON입니다. [후보 CSV 필드 안내](docs/candidate-csv.ko.md)를 참고하세요.

후보 제목은 모델이 선택한 연산자와 초점을 연구 질문으로 표현한 것입니다. 자유로운 기전 서술이나 신규성 검증을 자동 완료한 것으로 보지 않습니다. 확률은 선택 확률이며 가설의 과학적 진실 확률이 아닙니다.

문헌 확인과 System 2 상세 검토는 Codex 스킬에서 이어 수행합니다. 실제 사람의 채택은 별도 결정입니다. 전수 검사 완료와 과학적 검토 완료는 구분합니다.

계획·모델 판단은 디스크에 저장하지만 입력 표와 보고서 후보는 메모리에 읽습니다. 무제한 규모나 아직 측정하지 않은 속도를 보장하지 않습니다.
